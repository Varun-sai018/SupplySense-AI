# SupplySense Database Schema & Migrations

## Purpose
This directory contains the database schema initialization scripts (migrations) for the `supplysense` orchestration, event-tracking, dependency evaluation, and execution tracking tables.

## Migration Sequence & Order
When the Docker MySQL container starts for the first time, scripts mounted into `/docker-entrypoint-initdb.d` execute in alphabetical/lexical order. The migrations must run in this exact order due to foreign key relationships:

1. `001_create_dataset_metadata.sql`
   - **Purpose:** Creates the `dataset_metadata` table.
   - **Function:** Tracks registered datasets (e.g., Orders, Products, Sellers), their storage tables, version numbers, row counts, and synchronization status (`WAITING`, `READY`).
   - **Role:** Base table referenced by event and dependency tables.

2. `002_create_dataset_events.sql`
   - **Purpose:** Creates the `dataset_events` table.
   - **Function:** Records granular dataset update events generated by source changes or simulation.
   - **Foreign Keys:** References `dataset_metadata(dataset_id)`.
   - **Status Lifecycle:** `NEW` → `PUBLISHED`.

3. `003_create_pipeline_dependencies.sql`
   - **Purpose:** Creates the `pipeline_dependencies` table.
   - **Function:** Stores pipeline definitions and dependency evaluation rules (`condition_type` of `ALL`, `ANY`, or `QUORUM`, and optional `required_count`).
   - **Role:** Parent definition table for pipeline dependency topologies.

4. `004_create_dependency_datasets.sql`
   - **Purpose:** Creates the `dependency_datasets` junction table.
   - **Function:** Maps many-to-many relationships between pipelines and the required datasets they depend on.
   - **Foreign Keys:** References `pipeline_dependencies(dependency_id)` and `dataset_metadata(dataset_id)`.

5. `005_create_pipeline_decisions.sql`
   - **Purpose:** Creates the `pipeline_decisions` table.
   - **Function:** Audit log storing decisions made by the Dependency Engine (`TRIGGER` or `BLOCK`), including condition evaluated, total required count, ready count, and evaluation reason.

6. `006_create_pipeline_executions.sql`
   - **Purpose:** Creates the `pipeline_executions` table.
   - **Function:** Tracks triggered pipeline execution instances (`RUNNING`, `COMPLETED`, `FAILED`).
   - **Idempotency Guarantee:** Enforces a unique composite key `(pipeline_name, triggering_event_id)` to ensure that duplicate Kafka events do not cause duplicate pipeline runs.
   - **Foreign Keys:** References `pipeline_decisions(decision_id)`.

## Schema Initialization vs Data Ingestion
**IMPORTANT:** The schema initialization process ONLY creates the foundational orchestration and tracking tables for SupplySense AI.

The historical **Olist CSV dataset is NOT automatically ingested** during Docker startup, as it is a large batch of source data.
- The Olist historical CSVs are purely source data, representing an external system.
- They are NOT automatically considered real-time data.
- The Event Generator currently simulates dataset updates over this data.

To load the Olist data, you manually run the ingestion script *after* the database is running:
```bash
python data/scripts/upload_olist.py
```

---

## How to Reset the Local Database
To completely wipe the database (including Olist data, decision logs, and event history) and re-run migrations from scratch:

> **WARNING:** Destructive operation. Destroys all local MySQL data volumes.

1. Stop the containers and remove the database volume:
   ```bash
   docker compose down -v
   ```
2. Restart the containers:
   ```bash
   docker compose up -d
   ```
3. Re-ingest source data if needed:
   ```bash
   python data/scripts/upload_olist.py
   ```

## Table Summary

| Table Name | Primary Role | Key Columns |
|---|---|---|
| `dataset_metadata` | Tracks registered datasets & versions | `dataset_id`, `dataset_name`, `current_version`, `status` |
| `dataset_events` | Change-data-capture / simulated events | `event_id`, `dataset_id`, `dataset_version`, `event_status` |
| `pipeline_dependencies` | Rule definition (ALL / ANY / QUORUM) | `dependency_id`, `pipeline_name`, `condition_type`, `required_count` |
| `dependency_datasets` | Dependency-to-dataset mapping | `id`, `dependency_id`, `dataset_id` |
| `pipeline_decisions` | Dependency Engine decision log | `decision_id`, `pipeline_name`, `decision`, `reason` |
| `pipeline_executions` | Pipeline execution & idempotency tracking | `execution_id`, `pipeline_name`, `triggering_event_id`, `status` |
| *Olist Tables* | Historical e-commerce source data | `olist_orders`, `olist_order_items`, `olist_products`, etc. |
